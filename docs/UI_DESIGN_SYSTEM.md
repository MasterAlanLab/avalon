**盒模型**：原稿 CSS 默认是 content-box，凡未声明 `box-sizing:border-box` 的元素，width／height 不含 padding。实测受影响的有：

- 手机状态栏：54 加顶部 4 内边距，总高 58。
- 手机主分段：总高 36。
- 桌面侧栏：220 加左右各 10 内边距，总宽 240。
- 桌面工具列表：250 加左右各 12 内边距，总宽 274。
- 桌面顶栏模式分段：总尺寸 204×32；日志分段 424×32。
- **分隔线在尺寸之外**：`min-height:44px;border-bottom:0.5px` 的行实际高 44.5（`AvBorder.hairline`）。同理：节点行 56.5、设备与应用行 52.5、标签栏 83.5、Linux 标题栏 46.5、桌面工具栏 56.5、表头 30.5、GEO 表行 42.5；侧栏总宽 240.5，工具列表 274.5。只有带开关或副标题的设置行写明了 `padding:6px 16px;box-sizing:border-box`，总高就是 44（桌面 42）。
- **textarea 是行内块**：坐在所在行的基线上，下方还有该行字体的下沉部分。订阅链接框 `min-height:64px` 实际占 68（桌面 60 实际占 63）。

取值时必须先判断盒模型。

分隔线有两种起点，需逐一还原：

- **有前置图标或「外层留边、内层画线」的行**：分隔线从文字处开始（缩进）。
- **设置项、表单项**：分隔线贯穿整行。

## 2. Flutter 实现策略

### 2.1 基础

- **应用外壳**：使用 `CupertinoApp`，自带 Cupertino 路由、文本选择与本地化；不使用任何 Material 组件。
- **主题**：V3 令牌通过 `AvTheme` 下发（`context.av`），不依赖 Material ThemeData。
- **本地化**：`locale: zh-CN`，确保中文字形用简体字形，否则 Android 可能回退到日文字形。
- **单一来源**：令牌全部来自 `tokens.dart`（颜色、字号、阴影、曲线、时长），组件不得写死数值。
- **Android 渲染兼容**（D116）：当前 Flutter pin 下，仅 Android 12 及以上的 MT6855 使用已通过真机对比的 Skia 后端，其余设备沿用 Flutter 默认选择；不改变动效参数或模糊材质。工具链升级后须重新验证该兼容项。

### 2.2 组件

组件与令牌由 `packages/av_design/lib/src/` 维护，页面使用公开的 `av_design.dart` 入口。

### 2.3 路由与转场

- **推入／返回**：`AvPageRoute`（`av_design` 的 `routes.dart`）。新页从 100% 滑入；下层页按 V3 `ios-pop` 移到 −30% 并淡到 0.6，淡出时透出页面背景色。时长 500 ms，曲线 `(.32,.72,0,1)`。返回时按时间倒放同一组运动，因此两个方向都是减速收尾。
  - 边缘右滑返回：从左缘 20 pt 内起手，跟手时为线性；松手时按速度（每秒 1 屏宽）或位置（过半）决定返回或回弹，用 350 ms 的 V3 曲线收尾。
  - V3 原型一次只渲染一个屏幕：导航栏瞬间切换，只有内容区滑动。这是原型的限制，不照搬，这里整页（含导航栏）一起滑动（D63）。
- **底部弹层**：`AvSheetRoute`，继承 `CupertinoSheetRoute`。背景页缩小、加圆角并露出黑底，可下拉关闭；滚动内容使用路由提供的 controller。
  - 时长改为 550 ms。
  - 框架在弹层内部写死了自己的曲线，所以路由先把动画值经过「框架曲线的反函数 ∘ V3 曲线」重映射，再交给框架；合成后的曲线正好是 V3 的 `(.32,.72,0,1)`，背景页缩放同样处理。拖拽过程中直接使用原始值。
- **标签切换**：每个标签有独立 Navigator，子页面保留标签栏；切换时 `AvFadeSwap` 播放 320 ms 渐变加 0.985 缩放。
- Android 根标签在转场期间通过固定重绘边界与 1 倍输入缩放滤镜复用内容，结束时撤去滤镜（D121）。曲线、时长、缩放幅度和底栏材质保持；内容变化仍会重绘，运动中文字允许轻微采样差异，静止画面保持原始绘制。

### 2.4 平台细节

- **Android**：edge-to-edge，状态栏和导航栏透明；状态栏图标随主题切换；滚动用 `BouncingScrollPhysics`，与 iOS 一致。
- **iOS**：Info.plist 设置 `CADisableMinimumFrameDurationOnPhone=true` 以启用 120 Hz。
- **触感反馈**：开关与分段 `selectionClick`，电源键 `lightImpact`（D64，已确认）。
- **细线**：2× 以上屏幕绘制 0.5 pt；1× 屏绘制 1 物理像素，避免发虚。
- **日志换行**：用零宽空格模拟 `break-all`（`AvType.breakAll`，仅用于显示）。
- **桌面窗口**：外观由各平台 runner 原生实现（D69），window_manager 只管生命周期。macOS 在 `MainFlutterWindow.swift` 中定位系统红绿灯；Windows 自绘按钮须保留 Win11 贴靠布局，Linux 使用客户端装饰。验收范围见 [STATUS](STATUS.md)。

## 3. 视觉核对与平台边界

本节维护复测条件、平台边界与已知差异。当前结果及待验收项见 [STATUS](STATUS.md)。

### 3.1 静态对照

手机参考画框为 390×844 pt @3×；核对元素位置、尺寸、颜色、圆角、分隔线和浅深色。比较前按真实安全区对齐内容，不将系统栏差异当作页面偏移。

### 3.2 动效测量

按 §4 录屏跟踪滑块和页面边缘，核对 §1.5、§2.3 的运动参数。`packages/av_design/test/routes_test.dart` 保留长拖返回、短拖回弹和声明式页面更新的交互回归，不再逐个断言动画内部时点。

Android 手势导航可由系统接管左缘返回，页面执行常规返回动画；iOS 的左缘手势由应用路由处理。曲线对照与流畅度测量分别验证：正确的时长和轨迹不代表帧耗时已经达标。

### 3.3 对照范围

对照范围包括根页、添加表单和工具子页，以及登录、验证码、账号权益等真实状态。桌面参考窗口为 1280×820 逻辑像素；分别核对 macOS、Windows、Linux 外框、侧栏、工具栏、网格与对话框。V3 未画的内容使用产品规格及 D67、D115、D123，不以画廊演示数据判断功能是否可用。

### 3.4 平台排版

- 跟随系统默认字体，数字使用等宽数字，密钥和日志使用平台等宽字体（D62）。
- 使用真实安全区，不伪造设计稿状态栏和手势条高度；仪表盘按可用高度铺满。
- 不模拟浏览器行高取整；大标题固定 50 pt，其余文字使用原生排版。

### 3.5 同字体参考画布

按需参考画布从宿主 macOS 读取 SF Pro 与苹方（D68），排除字体差异后比较布局。D119 后不保留页面截图基线；输出仅供本次人工对照。

画布通过 `tool/fidelity/deck_canvas.dart` 按 390×873@1×、状态栏 58、底部 34 渲染开发画廊，供人工核对布局、字体和完整页面底部。

### 3.6 iOS 复测边界

iOS 使用系统字体和真实安全区。模拟器复测入口见 §4 第 10 步；调试版的首次推入受 JIT 影响，需预热后核对轨迹，不以该耗时评判发行性能。侧滑应跟手、可完成返回或取消回弹，弹层背景按 D63 压暗。触感反馈需在真机验证。

### 3.7 macOS 窗口复测

- **窗口外观**：红绿灯由系统绘制，三个按钮圆心在 (24, 24)、(44, 24)、(64, 24)，窗口缩放到最小尺寸后位置不变；失去或获得焦点时由系统切换灰色和彩色。
- **命中测试**：顶部工具栏的点击交给 Flutter 视图，红绿灯位置交给系统按钮；拖动、双击标题区与悬停需使用真实鼠标核对。
- **截图颜色**：`screencapture` 的 PNG 带显示器色彩配置，需转为 sRGB 再比较（`mac.sh` 已处理）。

## 4. 如何复测

1. 安装开发画廊：构建时加 `-t gallery/main.dart`（例如 `flutter build apk -t gallery/main.dart`）。
2. 执行 `tool/fidelity/capture.sh --setup`。
3. 用 `capture.sh OUT NAME [x y]...` 点到目标页并截图。
4. 如有另行提供的参考截图，用 `compare.py reference.png capture.png out.png` 生成并排图；界面要求以本文为准。
5. 动效测量：用 `adb shell screenrecord` 录屏，再用 `track.py` 跟踪并与 V3 曲线对比。`thumb` 模式跟踪滑块；`edge` 模式跟踪推入页的白色单元格左缘，配合 `FROM TO` 给出屏幕外的起止位置。起点按样本拟合。
   - 如果 screenrecord 输出「recorded 0 frames」（系统设置页滑动也录不到），说明模拟器的虚拟显示失效。可尝试冷启动模拟器；未恢复时改用可正常录屏的设备测量，当前录屏只做目视检查。
   - 宿主侧的 `adb emu screenrecord` 只有 5–10 fps，只适合目视检查；此时用 `SCALE=2.769` 换算（1080 宽画面中的 390 pt 画布）。
6. Android 模拟器上的桌面布局：执行 `adb shell wm size 2560x1640` 与 `adb shell wm density 320`，再用 `flutter build apk -t gallery/main.dart --dart-define=AV_DESKTOP=mac` 构建；`AV_DESKTOP` 可选 `mac`、`windows` 或 `linux`。按 §1.6 核对窗口、侧栏和内容区布局；原生窗口与系统交互须在对应桌面检查。
7. 结束后执行 `capture.sh --reset` 复原模拟器显示。
8. 按 D119，默认 `flutter test` 仅运行核心交互与状态故障回归，不维护页面截图基线。视觉修改后，在开发画廊或真实应用中按本文核对浅深色、长名称、大字号和窄屏布局；页面推入、返回与弹层动画使用设备录屏复测。
9. 同字体画布（macOS 系统字体，按需运行）：在 `app/` 执行 `flutter test --update-goldens --dart-define=AV_DECK=true tool/fidelity/deck_canvas.dart`，人工核对渲染结果（§3.5）。

10. iOS 模拟器：`flutter build ios --simulator --debug -t gallery/main.dart`，然后执行 `tool/fidelity/ios.sh launch build/ios/iphonesimulator/Runner.app`。
    - `ios.sh shot OUT NAME "tap X Y"…` 按逻辑点操作并截图；还支持 `drag X1 Y1 X2 Y2 MS`、`dark 0|1`、`account paid|free|loggedOut`。标签栏在 y=790。
    - 驱动真实应用（而非画廊）时改用 `-t gallery/app_main.dart` 构建：同一套遥控，另有 `hold X Y MS`（长按）和 `type 文本`（写入当前聚焦的输入框）。订阅内容可由本机 `127.0.0.1` 上的临时 HTTP 服务提供（模拟器与宿主共用网络）。
    - 遥控靠 app 临时目录里的标记文件开启（iOS 上 Dart 读不到进程环境变量），所以平时运行和真机不受影响。
    - 此脚本面向画廊及 `gallery/app_main.dart` 遥控测试入口。正常更新模拟器上的主应用应构建 `-t lib/main.dart`，再用 `simctl terminate`、`install`、`launch` 覆盖安装（保留本地数据），命令见 [app/README](../app/README.md#update-the-main-app-on-an-ios-simulator)。三个入口共用 bundle ID 与输出路径，安装前应重新构建目标入口。
    - 录屏：`xcrun simctl io booted recordVideo --codec=h264 OUT.mov`，用 Ctrl-C 结束。视频压缩后白色约为 253、背景约为 240，`track.py` 的阈值已按此设定。

11. macOS：`flutter build macos --debug -t gallery/main.dart`，然后执行 `tool/fidelity/mac.sh launch`，再用 `mac.sh shot OUT NAME "tap X Y"…` 截取窗口（命令同第 10 步）。只截 app 窗口，不截整个屏幕；终端需要「屏幕录制」权限。窗口大小会沿用上次退出时的尺寸。

**启动动画**（`app/lib/app/startup_splash.dart`）：每次冷启动全屏播放 1 秒，按 1080×1920 的设计尺寸等比缩放居中。时间线（毫秒）：左轨 80–320、右轨 240–480，三级横档 410–550、500–640、590–730，两个端点 220–340、360–480 淡入，「Avalon」与「ROUTE · CONNECT · CONTROL」730–910 淡入。动画播完且本地数据打开后才进入应用；数据打开得慢时停在最后一帧，打不开时进入启动错误页。

**颜色跟随**：动画先按设备的深浅色绘制，读到设置后改用应用自己的外观（深色／浅色）。Android 12 起系统先显示一个空白的系统启动页（只有启动背景色，不显示图标），动画等它消失后才开始播放（最多等 1.5 秒）；应用把自己的外观交给系统（`UiModeManager.setApplicationNightMode`），系统记住它，下次启动时系统启动页的底色就和应用一致，而不是跟随设备的深色模式。Android 12 以下没有系统启动页，进程起来之前的窗口仍跟随设备设置。iOS 的启动屏只有启动背景色，随设备深浅色。
